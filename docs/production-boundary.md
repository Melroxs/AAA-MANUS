# Production boundary

The app now uses persistent backend password sessions (`aaa_app_session`) with `SameSite=None; Secure` cookies, scrypt password verification, server-side role checks, idempotent seeding for all six fictional accounts, and MySQL-compatible application tables for accounts, sessions, passengers, drivers, bookings, append-only booking events, locations, and document records. The configured Webdev database is MySQL-compatible; Neon/PostgreSQL and Better Auth were not provisioned in this environment, so the implementation does not claim those specific external services are active. Manus OAuth remains available as a separate starter path.

The verified backend workflows include demo login, protected booking reads/creates, dispatcher assignment with approved-driver and time-conflict checks, explicit driver status transitions, and eligible-trip location writes. R2 upload/download endpoints are implemented but return a clear configuration error until `R2_ENDPOINT`, `R2_ACCESS_KEY_ID`, `R2_SECRET_ACCESS_KEY`, and `R2_BUCKET_NAME` are supplied. Required production setup still includes a private Cloudflare R2 bucket named `aaa-mvp`, notification provider credentials, a map provider, rate limiting, and a review process for driver identity documents. Do not represent simulated GPS, development notifications, basic document review, or demo identities as verified operational facts.
