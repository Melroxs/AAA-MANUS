# Production boundary

The app now uses persistent backend password sessions (`aaa_app_session`) with `SameSite=None; Secure` cookies, scrypt password verification, server-side role checks, idempotent seeding for all six fictional accounts, and MySQL-compatible application tables for accounts, sessions, passengers, drivers, bookings, append-only booking events, locations, and document records. The configured Webdev database is MySQL-compatible; Neon/PostgreSQL and Better Auth were not provisioned in this environment, so the implementation does not claim those specific external services are active. Manus OAuth remains available as a separate starter path.

The verified backend workflows include demo login, protected booking reads/creates, explicit caregiver authorization records, dispatcher assignment with approved-driver/active-vehicle and time-conflict checks, cancellation with released assignments, explicit driver status transitions, eligible-trip location writes and authorized stale-location reads, persisted in-app notifications with read state, provider-ready driver verification submission/review routes, and non-destructive seed behavior. R2 upload/download endpoints and the browser upload control are implemented but return a clear configuration error until `R2_ENDPOINT`, `R2_ACCESS_KEY_ID`, `R2_SECRET_ACCESS_KEY`, and `R2_BUCKET_NAME` are supplied. Identity verification remains `provider_unconfigured` until `KYC_PROVIDER_URL` and `KYC_PROVIDER_API_KEY` are supplied; no driver is labeled verified without provider-backed review. Email, SMS, WhatsApp, map tiles, liveness/facial matching, rate limiting and external identity-verification calls are not activated in this environment. Do not represent simulated GPS, development notifications, basic document review, or demo identities as verified operational facts.
